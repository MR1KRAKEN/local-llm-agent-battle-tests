# flint-24B (MoE) — быстрая, но думает больше, чем делает

**Языки:** Русский (этот файл) · [English version](../flint-24b.md)

**Источник:** [lmstudio-community/flint-GGUF](https://huggingface.co/lmstudio-community/flint-GGUF)
(веса — [RecursiveSI/flint](https://huggingface.co/RecursiveSI/flint))
**Файл:** `flint-Q4_K_M.gguf`, 22.5 ГиБ
**Архитектура:** MoE, 256 экспертов, **6 активных на токен**, 49 блоков, собственный контекст 262 144
**Рантайм:** llama.cpp CUDA `b12248`, `--jinja`, KV-кэш q8_0
**Дата теста:** 12 ноября 2026

> Тестирование проведено под надзором **DeepSeek-V4.1-Flash** (оркестратор DSH, `deepseek-account/deepseek-flash`).

## Результат коротко

**Вердикт: ⛔ как агент непригодна при любом проверенном бюджете рассуждений.**

| Метрика | Значение |
| :--- | ---: |
| Скорость обычной генерации | **49.9 tok/s** |
| Скорость на длинных прогонах (128К контекст) | **55.3 tok/s** |
| Максимум зафиксированный | **62.7 tok/s** |
| Вызовы инструментов через API | работают (1.8 с на вызов) |
| Вызовы инструментов как субагент DSH | **0** в решающем прогоне |
| Калькулятор WinForms | **не собран** |
| Консольные калькуляторы | не дошла |

Для сравнения: самые быстрые в основном наборе — Qwen3.5-9B (69.7 tok/s) и Nemotron-30B (60.6 tok/s).
flint между ними, но при файле в **22.5 ГиБ** против 5.24 и 17.6. Разреженность MoE реально окупается:
на токен работают лишь 6 экспертов из 256.

## Что произошло

Задача та же, что у остальных: написать калькулятор WinForms, собрать, опубликовать exe.
Проверены четыре режима, промт одинаковый и минимальный.

| Бюджет рассуждений | Язык | Результат |
| :--- | :--- | :--- |
| `--reasoning-budget 0` (выключено) | EN | написала оба файла, затем **28 правок подряд** с `old_string was not found`; сборки нет |
| `--reasoning-budget 6000` + «Stop analysing. Call the tool now.» | EN | **12 перезаписей `Program.cs`**: полные записи на 6 283 символа чередуются с обрезками на 116 и 12 символов; сборки нет |
| `--reasoning-budget 16384` | EN | **16 263 токена в рассуждения**, 279 с, файл так и не дописан |
| `--reasoning-budget 32768` | EN | **32 771 токен в рассуждения**, 593 с, **ноль вызовов инструментов** |
| без ограничения (`-1`) | RU | вырождение в повтор `<think></think>` |

Решающая строка — последняя из бюджета 32768: контекст 128К, лимит ответа 40К, бюджет размышлений 32К —
и модель потратила **всё**, что ей разрешили, на размышления, не сделав ни одного вызова.

## Качество кода

Код проверялся компилятором и рефлексией, а не на глаз:

| Находка | Детали |
| :--- | :--- |
| `CS1513` | файл обрывается на 217-й строке: класс и namespace не закрыты |
| Скрытая `CS1729` | `new Font("Segoe UI", 10, FontStyle.Regular, GraphicsUnit.Point, 10, false, false, false, false)` — **9 аргументов**, а у `System.Drawing.Font` есть только конструкторы на 2, 3, 4, 5 и 6 аргументов (проверено рефлексией) |
| Локаль | `result.ToString()` без инвариантной культуры — та же проблема с запятой, что у остальных |

Что она сделала **правильно** — и это стоит отметить, потому что на этом падали другие:

- `Keys.Oemplus` с маленькой `p` (Nemotron использовал `OemPlus` и получил `CS0117`);
- **не вызвала `base.OnKeyDown`** из своего обработчика `KeyDown` — та самая рекурсия, что уронила
  калькулятор Nemotron;
- разумная структура: поля, `UpdateDisplay`, `Calculate`, `AppendDigit`, `Backspace`, `ClearAll`.

То есть знания API есть, а дисциплины нет: десятки тысяч токенов размышлений и две незакрытые скобки
на выходе.

## Почему бюджет рассуждений не спасает

`--reasoning-budget N` работает на стороне сервера: когда счётчик исчерпан, llama.cpp вставляет токен
конца размышлений, и модель обязана начать отвечать. Модель об этом не знает.

Побочный эффект делает малые бюджеты хуже, а не лучше: обрыв может попасть **внутрь вызова инструмента**
и обрезать его аргументы. Именно это видно на прогоне с 6000 — полные записи на 6 283 символа чередуются
с 12-символьными огрызками, и модель переписывает файл снова и снова, потому что после обрезки он пустой.

`--reasoning-budget-message` позволяет подтолкнуть модель («Stop analysing. Call the tool now.»), но саму
обрезку не предотвращает.

## Что пишут на Hugging Face

В треде [«Flint can now run in llama.cpp and Unsloth Desktop!»](https://huggingface.co/unsloth/flint-GGUF/discussions/3)
говорят то же самое, только короче:

> «It just thinks and thinks and thinks lol. Not really usefull»

И ответ, очень точно описывающий наши замеры:

> «Так работают не очень умные модели: возьми посредственную модель, заставь её зацикливаться в
> размышлениях, и она в конце концов выдаст что-то полезное. Подвох — она потратит больше времени, чем
> большая медленная модель на ту же задачу».

Там же: *«20K+ reasoning tokens before it wrote any code»*, *«it's fast but not too smart»* и случай, когда
агент *«deleted everything including report»*.

Один человек нашёл рабочим `reasoning-budget = 20000`. У нас и 32 768 не дал ни одного действия — значит
дело в форме задачи, а не только в бюджете.

**Про скорость:** пользователь сообщает 49 tok/s на RX 7800 XT (Vulkan, Q4_K_XL, 23.3 ГиБ) — сходится с
нашими 55–62 tok/s на RTX 4070 Ti.

## Шаблон

Оригинальный шаблон от RecursiveSI содержит `| replace("\x00", "")`. Старые сборки llama.cpp и LM Studio
падали на нём с `Failed to parse Jinja template: Unexpected escaped character: x`. Исправлено:

- [PR #30929](https://github.com/ggml-org/llama.cpp/pull/30929) — *jinja: support hexadecimal string escapes*
- [PR #30928](https://github.com/ggml-org/llama.cpp/pull/30928) — *models: Add Flint model*

Оба влиты 21.10.2026. Наша сборка (`b12248`) их содержит, поэтому ошибки шаблона у нас не было.

## Вывод

flint — **быстрый генератор текста** с настоящим преимуществом MoE: 22.5 ГиБ весов и 55–62 tok/s на
12-гигабайтной карте. Вызовы инструментов на уровне API работают.

Как агент в харнессе с фиксированным бюджетом на шаг она не работает ни при одной настройке из
проверенных — 0, 6 000, 16 384 и 32 768 токенов. Либо не доводит цикл правок (бюджет 0), либо обрезает
собственные вызовы (малые бюджеты), либо тратит всё на размышления и не начинает действовать (16К и выше).

Хорошо подходит: одноразовые фрагменты кода, объяснения, черновики текста.
Не подходит: автономная многошаговая работа с потолком по токенам.

## Воспроизведение

```powershell
llama-server -m flint-Q4_K_M.gguf --host 127.0.0.1 --port 8090 --alias flint-24b-64k `
  -c 131072 -fa on -ctk q8_0 -ctv q8_0 --jinja -np 1 `
  --reasoning-format deepseek --reasoning-budget 32768 --no-webui
```

Замеры: AMD Ryzen 7 9800X3D, 64 ГБ DDR5, NVIDIA RTX 4070 Ti 12 ГБ, Windows 11, llama.cpp CUDA `b12248`.
