# Тесты локальных моделей в агентном цикле — обзор и методика

**Языки:** Русский (этот файл) · [English](../README.md)

Публикуемый набор отчётов по семи локальным моделям, прогнанным в одинаковой задаче:
**написать работающий WinForms-калькулятор на C#/.NET 8, собрать его в exe** и, дополнительно,
**консольные калькуляторы на Python, C, JavaScript, Rust и Java** с проверкой на 8 эталонных выражениях.

> **Тестирование проводилось под надзором DeepSeek-V4.1-Flash** (оркестратор DSH; в конфигурации провайдер
> `deepseek-account`, идентификатор модели `deepseek-flash`). Он поднимал серверы, ставил задачи,
> запускал автотесты, снимал метрики и сводил результаты. Код моделей он не писал и не исправлял.

## Как читать цифры

**Консольные тесты.** Каждому языку подаются на stdin восемь строк, вывод сравнивается построчно и
посимвольно:

| Вход | Ожидаемый вывод |
| :--- | :--- |
| `2+3` | `5` |
| `7*8` | `56` |
| `100/4` | `25` |
| `2.5+1.5` | `4` |
| `-4+10` | `6` |
| `0.1+0.2` | `0.3` |
| `(2+3)*4` | `20` |
| `10/0` | `error` |

`n / 8` — сколько кейсов совпало. Любая лишняя строка вывода сдвигает сравнение и тоже считается провалом.
Сумма «x / 40» — по пяти языкам (максимум `5 × 8 = 40`).

**WinForms.** Проверка была двойной: формальный автотест (`exe` в `dist`, процесс жив через 8 с, у процесса
есть заголовок окна, нажатия `1+2=` не роняют процесс) **и** ручная функциональная: клики по кнопкам мышью,
ввод с клавиатуры, сложный счёт (`46+54=100`, `123*45=5535`), деление на ноль. Формальный автотест
пропускал часть дефектов — например, падение на 3-й секунде после нажатия клавиши.

**«Сборок»** — число вызовов компилятора за прогон и сколько из них вернули `exit 0`. Запись `1 / 7`
читается «7 попыток, 1 успешная».

## Этапы

1. **BATTLE2** — одноразовый промт, свой харнесс, без цикла правок: `exe` не получила ни одна модель.
2. **BATTLE3** — субагенты DSH с `write`/`edit`/`read`/`pwsh`, точечные правки по ошибкам компилятора:
   `exe` собрали Nemotron и Qwen, gpt-oss и Bonsai — нет, LFM2 заблокирован движком.
3. **Доработка** — модели правили свои же файлы в подпапке `improved\`: удались только локальные правки.

## Оговорки

- Модели работали без доступа к интернету, кроме Qwen на одном из этапов доработки (3 страницы
  документации Microsoft Learn) — это отмечено в его отчёте.
- Оркестратор передавал моделям диагностику: тексты ошибок компилятора, стек падения, список симптомов.
  Правки делали сами модели.
- Лимиты по времени и шагам технически не форсировались, поэтому часть прогонов их превысила;
  значения замерены по факту, а не назначены.
